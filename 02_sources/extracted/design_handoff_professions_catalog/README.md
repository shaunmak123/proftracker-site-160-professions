# Handoff: Электронный каталог профессий (игра «Создай предприятие»)

## Overview

Справочный сайт для профориентационной игры «Создай предприятие». Участник получает в игре бумажную карту с профессией, заходит на сайт по общему QR-коду, вводит название профессии и получает полную информацию: чем человек занимается, каким оборудованием управляет, какую спецодежду и обувь носит, сколько зарабатывает в регионе, где этому учат и где можно работать.

**Что сайт делает:** даёт информацию по 160 профессиям, поиск по названию, каталог по 17 отраслям, история просмотров и закладки.

**Что сайт НЕ делает** (важно, это ограничение продукта, а не недоделка):
- не собирает и не проверяет команды — всю игровую механику дети ведут сами, офлайн;
- не сравнивает, не оценивает и не ранжирует профессии: нет рейтингов, звёзд качества, сортировки «по зарплате», подписей «востребованная / перспективная», нет топов. Все 160 профессий равны, разница только в том, кому какая подходит. Порядок в любом списке — алфавит, номер карты или время просмотра, никогда не «лучше/хуже»;
- не требует регистрации; всё, что запоминается (закладки, история), лежит в `localStorage` браузера.

Второй сценарий, который нужно поддержать: участник узнал у другого игрока название его профессии и ищет её на сайте. Отсюда важность поиска по названию с опечатками и подсказками — дети вводят название на слух.

## About the Design Files

Файлы в этом пакете — **дизайн-референс, сделанный в HTML**. Это прототип, показывающий структуру, состав экранов и поведение, а не продакшн-код для копирования. Задачу нужно понимать как **перенос этих экранов в целевой стек** (React / Vue / обычный статический сайт — на ваш выбор, если стека ещё нет) с использованием его паттернов и библиотек.

`design/wireframes.dc.html` — это Design Component: он открывается в браузере, но содержит служебную обёртку прототипирующей среды (`support.js`, тег `<x-dc>`, `<helmet>`). Смотрите его как картинку структуры и берите оттуда разметку блоков; не тащите обёртку в проект.

## Fidelity

**Low-fidelity / wireframe.** Это вайрфреймы: структура, состав блоков, иерархия и копирайт зафиксированы; визуальный слой — нет.

Прототип свёрстан на нейтральной чертёжной теме Industry (`design/industry-styles.css`) специально без брендинга. Финальное оформление будет по **брендбуку ЕВРАЗ** (партнёр игры) — цвета, шрифты, логотип, фото. При реализации закладывайте тему через CSS-переменные, чтобы бренд-слой менялся в одном месте: имена переменных в `industry-styles.css` (`--color-*`, `--font-*`, `--space-*`, `--radius-*`) можно оставить как контракт и переопределить значениями ЕВРАЗ.

## Screens / Views

Четыре экрана, мобильный приоритет (дети заходят с телефона по QR), плюс раскладка карточки для планшета и ПК. Мобильные макеты нарисованы на ширину 390 px, десктопный — 1120 px.

### 1. Стартовый экран / поиск (`1a` в прототипе)

**Purpose.** Точка входа с QR. Участник вводит название профессии со своей карты (или название, услышанное от другого игрока) и попадает на её страницу.

**Layout.** Одна колонка, боковые отступы 16 px. Сверху шапка-полоса высотой ~48 px с нижней границей 1 px, слева название каталога капслоком, справа кнопка меню 26×26. Дальше: надзаголовок-кикер, заголовок H2, абзац-пояснение, поле ввода, блок подсказок, основная кнопка, ряд из двух вторичных кнопок, сноска.

**Components.**
- Кикер: 10 px, моноширинный, letter-spacing 0.1em, uppercase, цвет `--color-accent-700`. Текст: «Игра «Создай предприятие»».
- Заголовок H2: 30 px, шрифт заголовков, межстрочный 1.12. Текст: «Взял карту? Узнай, кто это на самом деле».
- Пояснение: 13 px, 60 % непрозрачности текста. «Введи название профессии с карточки — покажем, что человек делает, чем управляет, сколько зарабатывает и где этому учат.»
- Поле ввода: класс `.input`, высота 44 px, размер шрифта 16 px (меньше нельзя — iOS зумит страницу при фокусе). Подпись сверху: «Название профессии с карты».
- Блок подсказок: рамка 1 px, фон `--color-surface`, регистрационные метки по углам. Строки по 10/12 px паддинга, разделены линией 1 px. Слева название профессии 15 px шрифтом заголовков, справа отрасль 11 px приглушённым. Показывается по мере ввода, от 2–3 символов; 3–6 строк.
- Основная кнопка: `.btn.btn-primary`, во всю ширину, высота 48 px, 16 px. «Найти профессию».
- Ряд вторичных кнопок: flex, gap 10 px, обе `flex:1`, высота 44 px. «Все 160 профессий» → каталог; «Случайная карта» → произвольная профессия.
- Сноска: 11 px, 50 %. «Не нашёл название? Проверь номер в углу карты или открой список по отраслям. Здесь нет лучших и худших профессий — все 160 равны, разница только в том, кому какая подходит.»

**Поиск.** Ищем по полю `name`, плюс синонимы: на картах колоды названия бытовые («автослесарь», «швея», «рабочий рудника»), а в базе — формальные. Нужны нечёткое совпадение (расстояние Левенштейна 1–2), поиск по подстроке и нормализация ё/е и регистра. Пустой результат — экран «не нашли», с предложением открыть каталог по отраслям (в прототипе не нарисован, стоит добавить).

### 2. Каталог по отраслям (`1b`)

**Purpose.** Обзор всех 160 профессий, когда название не ищется или просто интересно посмотреть.

**Layout.** Шапка со стрелкой назад и подписью «17 отраслей · 160 профессий». Ниже поле поиска по каталогу (высота 40 px) и вертикальный список отраслей с gap 8 px.

**Components.**
- Свёрнутая отрасль: рамка 1 px, паддинг 12 px, слева название 17 px шрифтом заголовков, справа счётчик профессий 12 px и шеврон.
- Раскрытая отрасль: рамка цвета акцента, шапка на фоне `--color-accent-100`, счётчик цветом `--color-accent-700`. Внутри — сетка 2 колонки, ячейки разделены линиями 1 px (grid gap 1 px по фону `--color-divider`), в ячейке название профессии 12.5 px, паддинг 10/8 px.
- Хвост списка: строка «Ещё 12 отраслей» с непрозрачностью 0.55 — раскрывает остаток.

Порядок отраслей — как в источнике данных; порядок профессий внутри — по номеру. Никакой сортировки по зарплате или «популярности».

### 3. Карточка профессии, мобильная (`1c`)

**Purpose.** Главный экран продукта. Здесь участник изучает свою профессию.

**Layout.** Шапка: стрелка назад, по центру «КАРТА 47 · МЕТАЛЛУРГИЯ» (10 px, моно, 0.08em), справа кнопка-закладка ☆. Тело в одну колонку, паддинг 16 px. Снизу липкая панель действий.

**Порядок блоков** (он же информационная иерархия):
1. Заголовок H2 34 px — название профессии.
2. Живая фраза 13.5 px, 65 % — поле `short` из данных, написана для 12–18 лет.
3. Фото профессии — рамка с угловыми метками, обёртка `.duotone`, высота ~180 px. Источник — изображение карты из колоды.
4. Плитка 2×1 с рамкой: «ЗАРПЛАТА В РЕГИОНЕ» и «УЧИТЬСЯ». Подпись 9.5 px моно, значение 20 px шрифтом заголовков.
5. Далее секции одного формата: разделитель сверху 1 px, паддинг 14 px сверху, заголовок H6 (13 px, uppercase, 0.08em, цвет `--color-accent-700`), содержимое 13 px.
   - «Основной вид деятельности» — абзац.
   - «Что делает на рабочем месте» — маркированный список, 4–6 пунктов.
   - «Что производит» — абзац.
   - «Оборудование и инструменты» — теги `.tag.tag-outline`, flex-wrap, gap 6 px.
   - «Спецодежда и СИЗ» — слева пиктограмма 78×96, справа текст.
   - «Спецобувь» — слева пиктограмма 78×60, справа текст.
   - «Где учиться» — код и название ФГОС жирным, ниже список учебных заведений (карточки с рамкой, 12.5 px), ссылка «Все заведения →».
   - «Где работать» — теги `.tag.tag-accent`.
   - «Похожие профессии» — горизонтальная лента карточек, ширина от 120 px. Формулировка нейтральная: «похожие», не «лучше» и не «вместо».
6. Липкая панель снизу: основная кнопка «Отметить, чтобы вернуться» (высота 46 px) и квадратная кнопка «поделиться» 46×46.

**Данные блоков** приходят из `data/professions.json`, поля перечислены ниже.

### 4. Мои профессии (`1d`)

**Purpose.** Вернуться к своей карте и к тому, что уже смотрел. Это личная история, а не «команда» и не коллекция для победы.

**Layout.** Шапка «Мои профессии». Далее:
- Блок «Моя карта» — рамка с метками, название и отрасль. Задаётся один раз при первом входе.
- Секция «Отмечено, чтобы вернуться» — карточки-строки: миниатюра 44×56, название 16 px, отрасль 11.5 px, звезда акцентного цвета справа.
- Секция «Недавно смотрел» — те же строки, звезда пустая (30 % непрозрачности) — можно отметить.
- Вторичная кнопка во всю ширину «Найти ещё одну профессию».
- Сноска 11 px: «Список хранится только в этом браузере — без регистрации. Порядок — по времени просмотра, никаких рейтингов.»

Никаких счётчиков прогресса, шкал «собрано N из 10» и оценок состава.

### 5. Карточка профессии, десктоп и планшет (`1e`)

**Layout.** Шапка 1120 px: слева название каталога, справа поле поиска 280 px и кнопки «Отрасли», «Мои профессии». Ниже хлебные крошки моноширинным 10 px. Основная сетка: `grid-template-columns: 400px 1fr; gap: 32px; align-items: start`.

- Левая колонка липкая (`position: sticky; top: 0`): фото 300 px в рамке с метками, плитка 2×2 (зарплата, срок обучения, отрасль, код ФГОС), основная кнопка во всю ширину.
- Правая колонка: H1 название, лид 16 px шириной до 60ch, затем сетка секций в 2 колонки (`gap: 0 32px`); секции «Что делает», «Оборудование», «Где учиться», «Где работать», «Похожие профессии» занимают всю ширину (`grid-column: 1/-1`), «Спецодежда» и «Спецобувь» стоят парой.
- Список «Что делает» на десктопе идёт в две колонки (`columns: 2`); обязательно `break-inside: avoid` на `li`, иначе пункт рвётся между колонками и текст накладывается.
- «Где учиться» — сетка из трёх карточек заведений; «Похожие профессии» — сетка из четырёх.

## Interactions & Behavior

- **Поиск.** Подсказки появляются по мере ввода (debounce ~150 мс), от 2 символов. Enter или тап по подсказке ведёт на карточку. Нечёткое совпадение обязательно.
- **Навигация.** Стартовый → карточка (поиск), стартовый → каталог → карточка, карточка → похожая профессия → карточка. Кнопка «назад» в шапке = история браузера. У каждой профессии свой URL (`/p/<slug>`), чтобы можно было поделиться ссылкой и чтобы работал QR прямо на карту, если позже понадобится.
- **Закладка.** Тап по ☆ в шапке карточки или по кнопке внизу добавляет профессию в «Отмечено». Состояние сохраняется мгновенно, без подтверждения; повторный тап снимает.
- **История.** Каждое открытие карточки пишется в «Недавно смотрел», не более 20 записей, дубликаты поднимаются наверх.
- **Поделиться.** Web Share API там, где есть; иначе копирование ссылки в буфер с тостом.
- **Раскрытие отрасли.** Аккордеон, можно держать открытыми несколько; состояние не переживает перезагрузку.
- **Пустые состояния.** «Ничего не нашли» — с подсказкой проверить название и кнопкой в каталог. Отсутствующие поля данных не рисуют пустую секцию: секция скрывается целиком.
- **Загрузка.** Данные — один JSON, грузится один раз; экраны загрузки достаточно скелетона на карточке.
- **Адаптив.** Один брейкпоинт ~900 px: ниже — мобильная одноколоночная карточка, выше — раскладка `1e`. Хиты не меньше 44 px в любой раскладке.
- **Доступность.** Фокус видимый: `outline: 2px solid var(--color-accent); outline-offset: 2px`. Подсказки поиска — `role="listbox"`, навигация стрелками. Контраст текста не ниже 4.5:1; акцент на светлом фоне для мелкого текста брать шагом `--color-accent-700`.

## State Management

Состояния немного, серверная часть не нужна — данные статические.

- `query: string` — строка поиска.
- `suggestions: Profession[]` — производное от `query`.
- `currentProfession: Profession | null` — из URL.
- `myCard: slug | null` — профессия с карты участника, `localStorage`.
- `bookmarks: slug[]` — `localStorage`.
- `recent: slug[]` — `localStorage`, максимум 20, LRU.
- `openIndustries: Set<slug>` — состояние аккордеона, только в памяти.

Данные профессий загружаются один раз (`data/professions.json`, ~160 записей) и держатся в памяти; индекс поиска строится на клиенте.

## Assets

- **Фотографии профессий** — 160 изображений из колоды карт, по одному на профессию. В прототипе на их месте штриховые плейсхолдеры. Имя файла для каждой профессии лежит в поле `image` (`<Название профессии>.jpg`); заказчик передаёт архив отдельно. Ожидаемая пропорция в карточке — примерно 4:3 на мобильном и 4:3 на десктопе, кадрирование `object-fit: cover`.
- **Пиктограммы спецодежды и спецобуви** — пока плейсхолдеры, нужны иконки или фото. Два размера: 78×96 и 78×60 на мобильном, 90×110 на десктопе.
- **Иконки интерфейса** — Lucide, толщина обводки 1.5.
- **Шрифты** — Barlow и Barlow Condensed (Google Fonts). При брендировании заменяются на шрифты ЕВРАЗ.
- **Логотип ЕВРАЗ и бренд-ассеты** — по брендбуку заказчика, в этом пакете их нет.

## Data

`data/professions.json` — 160 профессий и 17 отраслей.

```
{ industries: [{ name, slug, count }],
  professions: [{
    id,             // номер, 1–160
    industry,       // название отрасли
    name,           // название профессии
    slug,           // для URL
    short,          // одна живая фраза для 12–18 лет
    activity,       // основной вид деятельности
    description,    // что делает на рабочем месте
    product,        // что производит / роль в цепочке
    equipment,      // оборудование и инструменты
    clothing,       // спецодежда и СИЗ
    footwear,       // спецобувь
    salary,         // вилка по Свердловской области
    education,      // код и название ФГОС СПО
    employers,      // где можно работать
    similar,        // массив названий похожих профессий
    image,          // имя файла карточки
    contentStatus   // источник текста: из исходной таблицы / дописано (проверить)
  }] }
```

`data/professions.xlsx` — та же таблица в виде одного листа на 160 строк, для редактирования заказчиком. JSON пересобирается из неё.

**Что в данных ещё не финально:** зарплатные вилки — оценочные, требуют сверки; список учебных заведений и предприятий-работодателей пока обобщённый, персональных списков колледжей нет; девять профессий и пять кодов ФГОС дописаны и помечены в поле `contentStatus` как требующие проверки. Заказчик уточняет состав профессий и передаёт архив карточек.
